# Analytics Layer

## Overview

The Analytics Layer is responsible for transforming consolidated datasets into business-ready information through the generation of metrics, aggregations, indicators, and analytical views.

This layer operates on top of the unified data model produced by the ETL pipeline and serves as the primary source of information for dashboards, reports, and decision-support processes.

Its objectives are:

* Generate Key Performance Indicators (KPIs).
* Measure participation and engagement.
* Analyze geographic and demographic distributions.
* Evaluate data integration quality.
* Monitor user activity trends.
* Provide structured outputs for visualization.

# KPI Metrics

## Purpose

Provide a high-level overview of platform activity and user participation.

### Available KPIs

| Metric                  | Description                                       |
| ----------------------- | ------------------------------------------------- |
| Total Users             | Total number of consolidated users                |
| Registered Users        | Users originating from registration sources       |
| Workshop Registrations  | Users registered for events or workshops          |
| Workshop Attendance     | Users who attended at least one event             |
| Chatbot Users           | Users who interacted with conversational services |
| Multi-Source Users      | Users appearing in multiple data sources          |
| Unique Regions          | Number of represented geographic regions          |
| Unique Municipalities   | Number of represented municipalities              |
| Average Attendance Rate | Average attendance ratio across participants      |

# Territorial Analytics

## Purpose

Analyze user distribution across geographic areas.

### Regional Distribution

Calculates the number of users per region.

#### Outputs

* User count by region
* Percentage of total users by region

#### Example Use Cases

* Territorial coverage analysis
* Resource allocation planning
* Regional participation monitoring

---

### Municipality Distribution

Calculates participation at municipality level.

#### Outputs

* Top municipalities by user count
* Relative participation percentages

#### Example Use Cases

* Local engagement analysis
* Geographic targeting strategies

---

# Source Adoption Analytics

## Purpose

Measure how users interact across integrated systems.

This analysis evaluates the contribution of each source and identifies overlap between platforms.

### Source Presence Analysis

Determines whether users appear in:

* Registration systems
* Event systems
* Attendance systems
* Conversational platforms
* Additional integrated services

#### Outputs

| Metric               | Description                            |
| -------------------- | -------------------------------------- |
| Users by Source      | Number of users present in each source |
| Source Overlap       | Users appearing in multiple sources    |
| Multi-Source Users   | Users present in two or more systems   |
| Deeply Engaged Users | Users present in three or more systems |

---

## Benefits

* Measures platform adoption.
* Evaluates integration effectiveness.
* Identifies highly engaged users.
* Supports cross-system analysis.

---

# Conversion Analytics

## Purpose

Measure progression between user actions.

This domain evaluates how users move through participation stages.

### Registration-to-Attendance Funnel

Analyzes the relationship between registrations and actual attendance.

#### Metrics

| Metric                  | Description                           |
| ----------------------- | ------------------------------------- |
| Registered Users        | Users enrolled in events              |
| Attended Users          | Users who attended events             |
| Registered Only         | Registered but did not attend         |
| Attended Only           | Attendance without registration       |
| Registered and Attended | Completed the full participation path |
| Neither                 | No participation detected             |

---

### Conversion Rate

Formula:

```text
conversion_rate =
attended_users /
registered_users
```

#### Business Value

* Measures engagement quality.
* Evaluates event effectiveness.
* Identifies participation bottlenecks.

---

# Data Quality Analytics

## Purpose

Evaluate the reliability of the consolidation process.

This domain measures the effectiveness of entity resolution and record matching.

---

## Match Confidence Analysis

The platform assigns confidence levels during user consolidation.

### Confidence Levels

| Level     | Description                          |
| --------- | ------------------------------------ |
| HIGH      | Exact match using primary identifier |
| LOW       | Match using secondary identifiers    |
| UNMATCHED | No reliable match available          |

---

### Outputs

* Total records by confidence level.
* Percentage distribution of matches.
* Consolidation quality indicators.

---

## Benefits

* Monitors matching accuracy.
* Detects integration issues.
* Supports data quality initiatives.

---

# Temporal Analytics

## Purpose

Analyze platform growth and participation trends over time.

---

## User Growth Analysis

Tracks user acquisition using the earliest known interaction date.

### Outputs

* New users per period.
* Monthly user growth.
* Historical cumulative totals.

---

### Example Aggregation

```text
2026-01 → 1,250 users
2026-02 → 1,430 users
2026-03 → 1,612 users
```

---

## Cumulative Growth

Calculates total users accumulated over time.

#### Benefits

* Growth monitoring.
* Strategic planning.
* Capacity forecasting.
